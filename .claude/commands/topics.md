# /topics コマンド

## 目的

`agent-input/topics.md` に記載された学習トピック定義から、入力例・説明コメント・記入ガイドを取り除き、`/plan` が直接読み込めるシンプルで検証済みのトピック定義ファイルに正規化します。

## 入力

- `agent-input/topics.md`（Markdown）。現状は例やコメントを含むドラフト形式です。

## 出力

- 上書きで `agent-input/topics.md` にクリーンな内容を保存します。
  - 必要なフィールドのみを残し、入力例を削除したMarkdown形式。
  - フィールドは次のキーを必須とします（順不同）:
    - `学習トピック一覧`（箇条書き）
    - `事前知識レベル`（箇条書きまたは短文）
    - `学習目標`（箇条書き、各項目は「～できる」で終える）
    - `難易度`（`初級`/`初中級`/`中級`/`中上級`/`上級` のいずれか）
    - `難易度の詳細`（各難易度レベルの説明。`/plan` での正確な解釈のため必須）
    - `想定学習時間`（チュートリアル/課題実装/合計）
    - `チュートリアルの必要性`（`必要`/`不要`）
  - 任意フィールド: `補足情報`、チュートリアルが必要な場合の`必要な場合の理由`と`必要な場合の想定内容`。

## 前提条件

- 教員が手動で `agent-input/topics.md` にトピック情報を記入済みであること
- 作業用ブランチを手動で作成済みであること（例: `feature/define-topics`）

## 手順

1. `agent-input/topics.md` を読み込む。
2. HTML コメント (`<!-- ... -->`) と例示ブロック（`<details>` タグで囲まれた記入例や、`**例**:` のような行）を除去する。
3. 各セクションヘッダ（`## 学習トピック一覧` 等）を検出し、該当セクションの中身（プレースホルダ `{{ ... }}` を含む行も含む）を抽出する。
4. 必須フィールドが存在しない場合は、空のプレースホルダ行を追加して不足を明示する（例: `- {{ トピック1 }}` のようなプレースホルダ）。
5. `## 難易度` セクションの下に `### 難易度の詳細` サブセクションを追加し、各難易度レベルの説明を箇条書きで含める。
6. 出力は最小限のコメントのみとし、入力例を一切含めない。`### 難易度の詳細` は難易度の意味を伝えるために必須の情報として保持する。
7. クリーン化が完了したら `agent-input/topics.md` を上書き保存する。
8. 変更内容を確認し、コミット・プッシュします：
   ```bash
   git status
   git diff
   git add agent-input/topics.md
   git commit -m "clean: remove examples and comments from topics.md"
   git push origin <ブランチ名>
   ```

## バリデーションルールとドラフト生成

以下のルールに従って入力内容を検証してください：

### 必須チェック項目

- **難易度**: `初級`、`初中級`、`中級`、`中上級`、`上級` の5段階から選ばれていること
- **想定学習時間**: 以下の3つの項目が含まれていること（値は空でも可）
  - `チュートリアル:` で始まる行
  - `課題実装:` で始まる行
  - `合計:` で始まる行
- **学習目標**: 少なくとも1つ以上の項目が存在すること
- **チュートリアルの必要性**: `必要` または `不要` のいずれかが明確に記載されていること
- **学習トピック一覧**: 少なくとも1つ以上の項目が存在すること
- **事前知識レベル**: 少なくとも1つ以上の項目が存在すること

### バリデーション失敗時の対応

**重要**: バリデーションに失敗した項目や、プレースホルダが残っている項目については、エラーとして扱うのではなく、**Agent が文脈から適切な内容をドラフトし、教員の承認を得る**フローとしてください。

#### ドラフト生成の方針

- プレースホルダ（`$学習目標1` など）が残っている場合、既に記入されている他の項目や全体の文脈から、適切な内容を推測してドラフトしてください
- 不足している項目についても、同様に文脈から推測して補完してください
- ドラフトした内容には、各項目の末尾に `<!-- ドラフト: 確認してください -->` のコメントを追加してください

#### バリデーション結果の出力形式

**成功時**:
出力ファイルの先頭に以下を追加：
```markdown
<!-- VALIDATION: OK -->
```

**部分的にドラフトが含まれる場合**:
出力ファイルの先頭に以下を追加：
```markdown
<!-- VALIDATION: DRAFT -->

# ドラフト内容の確認

以下の項目は Agent がドラフトしました。内容を確認して、必要に応じて修正してください。

## ドラフトした項目

- **[項目名]**: ドラフトの理由と内容の説明

確認後、問題なければ `/plan` を実行してください。
```

## 注意事項

- このコマンドは、教員が `agent-input/topics.md` に記入することからワークフローが始まるため、**ブランチの作成を手動で行う必要があります**。
- このコマンドは人手による追加チェックの前処理を目的としています。自動で不要な情報を消しますが、最終的な内容は `/plan` 実行前に人が確認してください。
- 例示や補助コメントはすべて削除されます。必要な場合は `補足情報` セクションに明記してください。

## 実行後

- すべて記入済みの場合: ファイル先頭に `<!-- VALIDATION: OK -->` を追加してください。
- ドラフトが含まれる場合: ファイル先頭に `<!-- VALIDATION: DRAFT -->` と、ドラフトした項目の一覧を追加してください。
- 教員への通知: 処理結果を報告し、ドラフトした項目がある場合は確認を促してください。次のステップとして `/plan` の実行を案内してください。
