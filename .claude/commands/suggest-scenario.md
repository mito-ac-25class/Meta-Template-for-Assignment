# /suggest-scenario コマンド

## 目的

`/topics` で整理されたトピック定義を基に、課題として実装可能なシナリオ案を3つ提案します。
各シナリオは `agent-output/scenario0.md`, `scenario1.md`, `scenario2.md` に出力され、教員のレビューを待ちます。

## 前提条件

- `/topics` が実行済みで `agent-input/topics.md` がクリーン化され、コミット・プッシュされていること

## 入力

- `agent-input/topics.md`（`/topics` によってクリーン化されたMarkdown）

## 出力

- `agent-output/scenario0.md` - シナリオ案1
- `agent-output/scenario1.md` - シナリオ案2
- `agent-output/scenario2.md` - シナリオ案3

各ファイルは `templates/template.scenario.md` を基に作成されます。

## 手順

1. ブランチ `feature/suggest-scenarios` を作成してください。
   ```bash
   git checkout -b feature/suggest-scenarios
   ```

2. **既存シナリオファイルの確認とバックアップ**
   - `agent-output/` ディレクトリに `scenario0.md`, `scenario1.md`, `scenario2.md` が既に存在するか確認します。
   - 既存ファイルが存在する場合:
     - タイムスタンプ形式 `YYYYMMDD-HHMMSS` でバックアップディレクトリを作成: `agent-output/scenarios-backup-YYYYMMDD-HHMMSS/`
     - 既存の3つのシナリオファイルをバックアップディレクトリに移動
     - 教員に既存ファイルをバックアップした旨を通知

3. `agent-input/topics.md` を読み込み、以下の情報を把握します。
   - 学習トピック一覧
   - 事前知識レベル
   - 学習目標
   - 難易度
   - 想定学習時間
   - チュートリアルの必要性

4. トピックと学習目標に基づき、**異なるアプローチ・シチュエーションを持つ3つのシナリオ案**を考案します。
   - シナリオは実世界の問題や身近な題材を使用し、学生のモチベーションを高めるものにする
   - 各シナリオは同じ学習目標を達成できるが、異なる切り口やストーリーを持つ
   - 難易度や想定学習時間がトピック定義と整合するようにする

5. `templates/template.scenario.md` をテンプレートとして、`agent-output/scenario0.md`, `scenario1.md`, `scenario2.md` を作成します。

6. 各ファイルの `$` プレースホルダを具体的な内容で置換し、シナリオ案を完成させます。

7. **シナリオ評価マトリクスの作成**
   - `agent-output/scenario-evaluation.md` を作成し、3つのシナリオの評価マトリクスを出力します。
   - 評価マトリクスの形式は下記「## シナリオ評価マトリクス」セクションを参照してください。

8. 変更をコミット・プッシュしてください：
   ```bash
   git add agent-output/
   git commit -m "add: scenario proposals and evaluation matrix"
   git push origin feature/suggest-scenarios
   ```

## シナリオ案の作成ガイドライン

### 良いシナリオの条件

- **具体性**: 抽象的な問題ではなく、具体的なシチュエーションを設定する
- **親しみやすさ**: 学生が理解しやすい身近な題材を使用する
- **多様性**: 3つのシナリオは異なる領域・切り口を持つ
- **実現可能性**: 想定学習時間内に実装可能な範囲に収める
- **学習効果**: 学習目標を自然に達成できるストーリーになっている

### シナリオの多様性の例

以下のような観点で3つのシナリオを差別化してください：

1. **領域の違い**: ゲーム、業務システム、日常生活、科学計算など
2. **規模の違い**: シンプルな単一機能 vs 複数機能の連携
3. **アプローチの違い**: データ中心 vs 振る舞い中心、手続き型 vs オブジェクト指向

## シナリオ評価マトリクス

3つのシナリオ案とともに、`agent-output/scenario-evaluation.md` に以下の評価マトリクスを出力してください。
教員はこの評価マトリクスを参考に、採用するシナリオを決定します。

### 評価マトリクスの構成

以下の評価基準で各シナリオを5段階評価（1: 低い ～ 5: 高い）し、総合スコアを算出します：

| 評価基準 | 説明 | 重み |
|---------|------|------|
| **具体性** | シチュエーションが具体的で明確か | 1.0 |
| **親しみやすさ** | 学生にとって理解しやすく、身近な題材か | 1.0 |
| **実現可能性** | 想定学習時間内に実装可能な範囲か | 1.5 |
| **学習効果** | 学習目標を効果的に達成できるか | 2.0 |
| **拡張性** | 発展課題への展開が容易か | 0.5 |

**総合スコア計算式**: Σ(評価値 × 重み) / Σ(重み)

## 出力後のワークフロー

1. 教員は以下のファイルをレビューします:
   - `agent-output/scenario0.md`, `scenario1.md`, `scenario2.md` - シナリオ案
   - `agent-output/scenario-evaluation.md` - 評価マトリクス

2. 評価マトリクスを参考にしながら、採用するシナリオを決定します。

3. 採用するシナリオを決定したら、`agent-input/topics.md` の末尾に以下のフォーマットで追記します:
   ```markdown
   ## 採用シナリオ
   agent-output/scenario{N}.md
   ```

### 採用シナリオの記述ルール

**必須要件**:
- パスは**相対パス**で記述すること（リポジトリルートからの相対パス）
- パスは `agent-output/scenario0.md`, `agent-output/scenario1.md`, `agent-output/scenario2.md` のいずれかのみ使用可能
- セクション名は正確に `## 採用シナリオ` とすること

4. `/plan` を実行すると、採用シナリオの内容が課題プランに反映されます。

## 注意事項

- シナリオ案はあくまで提案であり、教員が選択・修正を行います。
- 3つのシナリオは互いに独立しており、組み合わせることは想定していません。
- シナリオの詳細（テストケースの具体的な内容など）は `/plan` で詳細化されます。
- このコマンドはオプションです。シナリオが明確な場合は `/plan` を直接実行できます。
- **再実行時の注意**: `/suggest-scenario` を再実行すると、既存のシナリオファイルは自動的にバックアップされます。採用シナリオを変更する場合は、`agent-input/topics.md` の採用シナリオセクションも忘れずに更新してください。

## 実行後

- 成功時:
  - 各シナリオファイルの先頭に `<!-- SCENARIO: READY FOR REVIEW -->` を追加してください。
  - 評価マトリクスファイルの先頭に `<!-- EVALUATION MATRIX: READY FOR REVIEW -->` を追加してください。
  - 教員に評価マトリクスを確認し、採用シナリオを決定するよう促してください。
